## 1. Project Overview

ECPriceResearchは、
韓国と日本の主要Eコマースプラットフォーム間における
価格およびマージン比較を自動化する個人プロジェクトです。

単なる価格比較ではなく、

- 異なる国  
- 異なる言語  
- 異なる通貨  
- 異なる商品データ構造  

を一つの基準に統合し、
**「どこで買い、どこで売れば利益が出るのか」**を
即座に判断できるよう設計しました。

本プロジェクトは、
- 日本就職を目的とした個人ポートフォリオであり  
- 実際のデプロイおよび運用を前提に開発されています

## 3. Key Contributions

### 3-1. Cross-Border Price Comparison Logic

**対象プラットフォーム**

- Amazon JP  
- Rakuten  
- Coupang  
- Naver  

各プラットフォームごとに異なるレスポンス構造を、
共通DTO（`PriceInfo`, `MarginCompareResult`）に統合しました。

- 為替レートAPIの適用  
- KRW ↔ JPY 自動変換  
- 原価と変換後価格を同時に提供  

👉 単なる「価格収集」ではなく、  
👉 ビジネス判断が可能なデータ構造を目指して設計しました。

---

### 3-2. Strict Language & Translation Rules

本プロジェクトの中核設計の一つは、
検索・翻訳ルールを明確な「憲法」として固定した点です。

**日本プラットフォーム**
- 日本語 → そのまま検索  
- 韓国語 → 日本語翻訳後に検索  
- 英語 → そのまま検索  

**韓国プラットフォーム**
- 韓国語 → そのまま検索  
- 日本語 → 韓国語翻訳後に検索  
- 英語 → そのまま検索  

出力もKR／JPトグルに応じて、
言語および**通貨表記**を厳密に分離しました。

👉 グローバルサービスで頻発する  
👉 言語・通貨の混線問題を構造的に防止しています。

---

### 3-3. AI Analysis (Basic / Premium)

- 検索時のAI呼び出しは1回のみ  
- 同時に以下の結果を生成：

  - **Basic**：短時間で読める要約分析  
  - **Premium**：詳細な深層分析  

Premiumボタンは再呼び出しではなく表示切り替えです。

AI分析は見せかけの機能ではなく、
価格データを解釈するための補助ツールとして設計しました。

---

### 3-4. Real-Time Streaming UX (SSE)

- Server-Sent Events（SSE）を用いた実装  
- プラットフォーム別の応答速度に応じて結果を配信：

  Naver → Coupang → Amazon → Rakuten  

ユーザーを待たせず、
「調査ツールを使っている感覚」を得られるUXを設計しました。

---

## 4. Problems & Debugging

開発過程で以下の問題を直接分析・解決しました。

- HTML構造変更による解析エラー  
- 言語ルール漏れによる検索結果不一致  
- 非同期処理中のSSEストリーム切断  
- 為替APIエラー時の全体ロジック停止  

各問題に対して、
原因分析 → 再現 → 構造改善
の流れで対応し、再発防止を重視しました。

## 6. Lessons Learned

ECPriceResearchを通じて得た主な学びは以下の通りです。

- グローバルサービスでは言語ルールがロジックと同等に重要  
- データ収集よりも解析構造の方が価値を生む  
- AIは多用するより、使いどころが重要  
- 個人プロジェクトでも運用前提でこそ意味がある  

本経験は、日本市場を前提としたサービス開発および
実務的なエンジニアリング理解を大きく高めました。
